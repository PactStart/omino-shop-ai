## Clarifications

### Session 2026-10-29

- Q: 没有真实商户号时，微信和支付宝购买积分怎样算完成？ → A: 三个渠道都要有下单。钱包当场扣余额并加积分。微信和支付宝用测试密钥做验签回调，成功只加一次积分，不连真实商户。
- Q: 本功能要不要让用户把返佣余额提现走？ → A: 要做提现申请和运营审核。实现前先把路径写入消费者契约和管理契约，本规格不预写路径。
- Q: 运营审核一笔返佣提现时，要做到哪一步才算完成？ → A: 申请时冻结相应返佣可用余额。通过必须打款到收款账号成功，才扣减冻结额并记提现流水。拒绝则解冻。打款失败不算审核完成。
- Q: 打款失败时，已经冻结的返佣余额怎么处理？ → A: 保持冻结，不记成功流水。运营可以再次打款，也可以拒绝并解冻。

## User Scenarios & Testing *(mandatory)*

本功能只有一个交付：购物用户、对话工具和运营能通过已有契约完成登录、选品、转链门闩、订单入账、积分和运营配置。页面与对话图不在本功能。

施工顺序就是下面的用户故事 1 到 11。前一个故事的独立测试未通过，不得开始下一个。优先级标签不改变这个顺序。

字段、路径、枚举和错误码以权威文档为准，本规格不另写一套。粘贴稿点名的错误码、事件名和表名是验收约束。

### User Story 1 - 能登录并记下邀请人 (Priority: P1)

购物用户用手机号验证码登录，得到访问凭证。带上有效邀请码时，立刻成为该邀请人的有效下级。研发用生成器产出数据访问映射，而不是为每张表手写一套，也不是从参考仓库抄来。

**Why this priority**: 没有登录和表，后面的接口无法归属到人。生成器是本功能新增的数据访问约束，必须在业务切片铺开之前落地。

**Independent Test**: 空库迁移后，用本地模拟短信完成一次登录；再用邀请码登录第二个用户，检查上级已写入且邀请关系为有效。对一张权威表运行生成器，得到对应的 XML 映射，且映射里没有联盟业务判断。

**Acceptance Scenarios**:

1. **Given** 空库，**When** 执行迁移，**Then** 表与 [`docs/data-model.md`](../../docs/data-model.md) 一致，主库仍是 PostgreSQL，没有 MySQL，没有美团平台码。
2. **Given** 本地允许模拟短信，**When** 用户请求验证码并提交正确验证码，**Then** 登录成功并得到访问凭证。错误或缺失凭证访问需登录的接口时，结果为 `40100`。
3. **Given** 邀请人已存在，**When** 新用户首次登录带上该邀请码，**Then** 同一事务写入 `app_user.inviter_id` 与邀请关系，状态为有效。自己邀请自己被拒绝。已有上级不被覆盖。邀请码创建后不可改。
4. **Given** 权威数据模型，**When** 运行集成的 XML 映射生成器，**Then** 为 DAO 产出 XML 映射文件。常规表映射来自生成器。手写映射只用于生成器表达不了的查询，且不得在映射文件里拼联盟逻辑，不得复制 mall-guide 的映射、表名或包名。

### User Story 2 - 开一轮对话并随时接上或停止 (Priority: P1)

已登录用户发一条消息后立刻拿到本轮编号。生成过程写入共享事件流。客户端用事件流订阅，断开后再订阅仍能看到已产生的内容。只有用户明确停止时，本轮才以取消结束。`test` 与 `prod` 的生成端调用 Agent；调不通时以失败结束，不把样例商品当成推荐。样例内容只允许在本地或测试双写里出现。事件名必须是对话契约里的真名。

**Why this priority**: 刷新不得变成取消，这是对话链路的验收底线。真正的意图图留到后续功能。

**Independent Test**: 登录后提交一轮，立刻得到本轮编号；断开订阅后再订阅，已写入的事件仍在；调用停止后终态为取消。不要求出现真实商品。Agent 不可用时终态是失败而不是样例完成。

**Acceptance Scenarios**:

1. **Given** 已登录用户，**When** 提交一轮对话，**Then** 立刻返回本轮编号，事件进入该轮的共享流。订阅间隔不超过 100 毫秒。
2. **Given** 本轮仍在生成，**When** 订阅断开，**Then** 生成不停止。再次订阅能从已有事件继续。
3. **Given** 用户请求停止，**When** 停止被接受，**Then** 写入终态 `cancelled`。已经写出的文本增量保留。对已结束的轮再次停止，结果仍成功且不报错。
4. **Given** 本功能尚未实现对话图，**When** `test` 或 `prod` 的生成端投递事件，**Then** 它调用 Agent。Agent 不可用时写入事件 `error`，`code` 为 `50020`，不得把样例商品写成成功完成。`local` 与自动化测试的测试双写可以使用样例内容。事件名只使用 [`docs/conversation.md`](../../docs/conversation.md) 锁定的名称。

### User Story 3 - 看详情、过转链门闩、留下浏览收藏和合集 (Priority: P1)

用户查看商品详情。平台没给销量或评价数时，结果是未知，而不是 0。去购买时，未授权得到 `40301` 且原因为 `NEED_AUTH`。响应里不出现联盟推广位标识。用户能浏览、收藏，并查看、移除自己的合集商品。

**Why this priority**: 这是购物主路径在服务端的门闩。页面不在本功能，但接口必须能被测试打通。

**Independent Test**: 对未授权用户调用转链，得到 `40301` / `NEED_AUTH`，且响应不含推广位标识。详情在销量未知时给出空值而不是 0。收藏同一商品两次只保留一条。

**Acceptance Scenarios**:

1. **Given** 平台未返回销量或评价数，**When** 读取详情或瘦快照，**Then** 这两项为空，不得写成 0。商品页链接不是购买链接。
2. **Given** 用户尚未授权该平台，**When** 请求转链，**Then** 结果为 `40301`，`error.reason` 为 `NEED_AUTH`，且不下发联盟推广位标识。
3. **Given** 用户已授权且转链成功，**When** 转链完成，**Then** 留下点击归因。密钥与推广位标识只存在于服务端环境。
4. **Given** 合集属于别人，**When** 当前用户移除其中商品，**Then** 结果为 `40300`。移除自己的商品后，列表不再包含该商品。

### User Story 4 - 四个电商平台可查询 (Priority: P2)

服务端能按淘宝、京东、拼多多、唯品会查询商品和详情。失败对调用方呈现为平台失败 `50010`。没有美团。

**Why this priority**: 订单同步和搜品都依赖这四个适配器，但登录、对话和转链门闩可以先用测试替身证明。

**Independent Test**: 四个平台各自有适配器。查询失败得到 `50010`。平台名单里不存在美团。适配器之外的业务层不直接调用联盟官方组件。

**Acceptance Scenarios**:

1. **Given** 平台为淘宝、京东、拼多多或唯品会之一，**When** 搜品或详情失败，**Then** 调用方得到 `50010`。
2. **Given** 任一请求使用美团平台码，**When** 校验平台，**Then** 被拒绝。仓库中不出现美团适配器、美团密钥或美团订单同步。
3. **Given** 联盟密钥，**When** 检查配置与响应，**Then** 密钥只在服务端环境变量，不出现在响应、日志或映射文件中。

### User Story 5 - 完成的订单只入账一次 (Priority: P2)

订单按平台游标增量同步。订单状态只有六种，结算状态只有三种。仅当订单已完成且待结算时，给下单用户记一笔返佣流水。同一订单重复同步不会再记一笔。消费者看不到媒体佣金。

**Why this priority**: 这是本功能的资金验收。入账规则错了，后面的钱包和积分都会错。

**Independent Test**: 构造一笔已完成且待结算、用户分成大于 0 的订单，同步两次，钱包流水只有一条，可用余额只增加一次。消费者订单响应不含媒体佣金、上级标识和流水标识。契约补上路径后，已登录用户申请提现会冻结相应可用余额；打款成功才扣减冻结额并记提现流水；打款失败保持冻结且可再次打款，拒绝会解冻。积分不能走这条申请。

**Acceptance Scenarios**:

1. **Given** 平台回传的订单，**When** 写入统一订单，**Then** `order_status` 只能是待支付、待发货、已发货、已完成、已取消、未知；对不上的原码写成未知。`settle_status` 只能是不结算、待结算、已结算。
2. **Given** 订单已完成、待结算、已归因且用户分成大于 0，**When** 同步入账，**Then** 只给下单用户写一条返佣流水，并回填结算状态。再同步一次不新增流水，也不增加余额。
3. **Given** 用户没有上级分成规则，**When** 入账，**Then** 不给上级写第二笔流水。已结算后平台改口，同步不改历史流水。
4. **Given** 消费者查询订单，**When** 查看响应，**Then** 不下发媒体佣金。分成比例使用可热更新的 `commission.user-share-rate`，默认 0.80。
5. **Given** 消费者契约与管理契约已经写明提现路径，且用户有足够返佣可用余额，**When** 已登录用户申请提现，**Then** 相应金额从可用余额划入冻结额。拒绝后冻结额回到可用余额，且没有提现流水。打款成功后冻结额减少，并记下一条提现流水。打款失败时冻结额保持不动，不记成功流水；运营可以再次打款，也可以拒绝并解冻。积分不能经提现离开积分账户。收款账号的完整值不出现在日志、对话工具响应或未授权的响应里。路径未写入契约前不得实现。

### User Story 6 - 用钱买积分，积分不能变回钱 (Priority: P2)

积分账户和返佣钱包分开。用户可以用微信、支付宝或返佣余额购买积分。积分不能提现，也不能转回钱包。余额不足时，对话轮次仍会建立，但以积分不足结束，并带上购积分卡。

**Why this priority**: 扣费只发生在服务端。对话图未接入前，仍须证明余额不足和支付入账的规则。

**Independent Test**: 用返佣余额买一笔积分，钱包减少、积分增加，两边各有流水。用测试密钥分别构造一笔微信回调和一笔支付宝回调，验签通过后各加一次积分，同一回调再送一次不加。不连接真实商户。尝试把积分转回钱包或按积分提现时被拒绝。余额低于起扣线时开一轮对话，订阅能看到积分不足终态。

**Acceptance Scenarios**:

1. **Given** 在售套餐且用户有足够返佣余额，**When** 用户以 `wallet` 下单，**Then** 当场扣减返佣可用余额并增加积分，两边各有一条不可改流水。
2. **Given** 在售套餐，**When** 用户以 `wechat_pay` 或 `alipay` 下单，并用测试密钥提交一笔验签通过的支付回调，**Then** 积分增加一条购买流水。同一回调再次提交不再加积分。验签失败不加积分。不要求真实商户扣款。
3. **Given** 任意入口，**When** 请求把积分提现或转回钱包，**Then** 没有这样的能力。积分余额不得为负。
4. **Given** 强制扣费且可用积分低于 0.01，**When** 用户开一轮对话，**Then** 仍返回本轮编号，事件流以积分不足结束，并包含购积分卡。未调用模型的轮次不扣积分。

### User Story 7 - 拿到海报模板和邀请关系 (Priority: P2)

用户能看到自己的邀请码、邀请链接，以及当前生效的海报模板和二维码矩形。服务端不合成成品图。落地页只能核对该码是否有效，看不到邀请人是谁。

**Why this priority**: 邀请数据被登录切片用到，模板下发是客户端贴码的前提。贴码和分享不在本功能。

**Independent Test**: 拉取海报列表，只得到原图地址和矩形，没有成品图接口。用邀请码公开查询，只得到有效或找不到，没有昵称和手机号。

**Acceptance Scenarios**:

1. **Given** 一张在生效期内的模板，**When** 用户拉取海报，**Then** 响应含原图与二维码矩形。没有合成成品的接口，也没有成品图存储。
2. **Given** 一个存在的邀请码，**When** 公开查询，**Then** 只表示有效。不存在则为 `40400`。响应不含邀请人昵称或手机号。
3. **Given** 模板已下架或超出生效时间，**When** 用户拉取，**Then** 该模板不出现。

---

### User Story 8 - 查知识库并留下带日志的工单 (Priority: P3)

对话工具能检索知识库。未命中必须明确未命中。建单时同时写下创建日志。之后每次状态、优先级、证据、回复或改派都追加日志，不改历史。

**Why this priority**: 工单是客服闭环。它依赖已登录用户，但不依赖真实联盟。

**Independent Test**: 检索一条不存在的规则，得到明确未命中。创建工单后，工单和时间线里各有一条创建记录。再改一次状态，日志增加一条，旧日志不变。

**Acceptance Scenarios**:

1. **Given** 知识库没有匹配，**When** 检索，**Then** 结果明确为未命中，不把模型补写的政策当成命中。
2. **Given** 已登录用户，**When** 创建工单，**Then** 同一事务写入工单和一条创建日志。
3. **Given** 已有工单，**When** 变更状态、优先级、证据、回复或处理人，**Then** 追加对应日志。历史日志不能被修改或删除。

---

### User Story 9 - 按端和渠道拿到版本、配置、公告和私信 (Priority: P3)

客户端按端、渠道和版本号检查更新、读取特殊配置和公告。运营能给某一个用户发站内信，不能把它当成群发。

**Why this priority**: 这些是运营投放能力。没有它们，主购物路径仍可测。

**Independent Test**: 用缺少客户端头的业务请求得到 `40001`。发布一条更高版本后，检查更新给出可选或强制。向一个用户发信后，只有该用户能读到。

**Acceptance Scenarios**:

1. **Given** 需要客户端头的业务请求缺少端、渠道或版本号，**When** 调用，**Then** 结果为 `40001`。登录、健康检查和支付回调不要求这些头。
2. **Given** 已发布的更高版本，**When** 检查更新，**Then** 按是否强制返回对应动作。同一端同一渠道同一天只有一条版本记录。
3. **Given** 多条匹配的特殊配置，**When** 客户端读取，**Then** 按优先级浅合并。公告按端、渠道、版本和时间过滤。
4. **Given** 运营指定一个用户发信，**When** 发送，**Then** 只有该用户的收件箱出现这封信。

---

### User Story 10 - 配置提示词和本轮用哪个模型 (Priority: P3)

运营能改八个固定提示词的正文，不能增删键。模型密钥加密保存，读取时看不到明文。每一轮对话注入全部提示词，以及按权重抽中的那一个模型。

**Why this priority**: 对话图尚未接入，但开轮时的注入内容必须在本功能定下来，否则后续功能会各写一套提示词。

**Independent Test**: 修改一条提示词后再开一轮，注入内容包含新正文和八个键。读取模型列表，响应没有密钥明文。同时上架的推荐问题超过 12 条时被拒绝。

**Acceptance Scenarios**:

1. **Given** 八个固定键，**When** 运营修改正文，**Then** 只更新正文。未知键为 `40400`。没有新增或删除键的入口。空正文被拒绝。
2. **Given** 已保存的模型密钥，**When** 读取模型，**Then** 只返回是否已设置和末四位掩码。更新时不传密钥则保留原密钥。日志和审计明细不含明文。
3. **Given** 至少一条可分流模型，**When** 开一轮对话，**Then** 注入八条非空提示词，以及本轮抽中的唯一模型。同一轮后续调用都用这一条。缺少任一提示词时不调用对话服务，本轮以对话失败结束。
4. **Given** 本地环境且没有任何可分流模型，**When** 开一轮，**Then** 允许不注入模型。测试与生产环境没有候选模型时，本轮失败。
5. **Given** 已有 12 条上架推荐问题，**When** 再上架一条，**Then** 结果为 `40001`。消费者只能看到上架中的问题。

---

### User Story 11 - 运营登录后才能改配置 (Priority: P3)

运营通过统一身份登录管理端。浏览器只访问管理接口，不持有访问令牌。未登录打不到业务接口。生产环境默认不能签发上帝视角票据。

**Why this priority**: 这是管理端的身份闸门。业务接口可以先写成，但未登录必须永远进不去。页面不在本功能。

**Independent Test**: 不带管理会话调用任一运营业务接口，被拒绝且得不到数据。生产默认配置下签发上帝视角票据得到 `40303`。仓库中没有管理员密码表。

**Acceptance Scenarios**:

1. **Given** 没有管理会话，**When** 调用运营业务接口，**Then** 被拒绝，得不到用户、订单、密钥或配置。健康检查仍可访问。
2. **Given** 统一身份可用，**When** 运营完成授权码登录，**Then** 使用 Authorization Code 与 PKCE S256，由管理服务完成兑换。浏览器不持有访问令牌。
3. **Given** 生产环境未单独打开上帝视角，**When** 签发短时用户票据，**Then** 结果为 `40303`。打开后签发的票据带上帝视角标记，并留下审计。

---

### Edge Cases

- 无访问凭证或凭证失效：需登录的消费者接口返回 `40100`。
- 管理端未登录：业务接口不可达，不返回业务数据。
- 转链时平台未授权：`40301`，原因 `NEED_AUTH`。响应、日志和客户端载荷都不含联盟推广位标识。
- 同一平台订单重复同步：返佣流水仍只有一条，余额不重复增加。
- 已结算后平台把订单改成取消：不自动追回，不改历史流水。
- 销量或评价数未知：为空，不得为 0。
- 订阅断开：生成继续。只有明确停止才写入 `cancelled`。
- 对已取消、已完成、已失败或已因积分不足结束的轮再次停止：成功且不重复制造终态。
- 自己邀请自己，或邀请码不存在：不写入上级。已有上级的用户再带另一个码：保持原上级。
- 积分余额不足仍开轮：返回本轮编号，终态为积分不足。余额不得被扣成负数。
- 同时两笔提现，或提现与用返佣余额购积分同时发生：先锁定该用户钱包行，再检查、再改余额。可用余额与冻结额不得为负。
- `test` 或 `prod` 上 Agent 不可用：本轮以事件 `error` 结束，`code` 为 `50020`，不投递样例商品。
- 用积分申请提现，或提现金额超过返佣可用余额：拒绝，且不把积分转成钱包余额。申请成功后，相应返佣可用余额进入冻结额。打款失败时冻结额保持不动，不记成功流水；再次打款成功才扣减，拒绝则解冻。
- 支付回调重复或验签失败：不重复加积分，验签失败也不加积分。微信和支付宝的验收不连接真实商户。
- 模型密钥、短信密钥、支付密钥、联盟密钥：不出现在响应、日志、审计明细或仓库文件中。
- 生产环境短信不得使用模拟通道。
- 推荐问题上架超过 12 条：`40001`。
- 上帝视角在生产默认关闭：`40303`。
- 映射生成器或手写映射中出现参考仓库的表名、包名或联盟分支：视为未完成。
- 对话事件使用契约以外的名字：视为未完成。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 实现与任务清单 MUST 按用户故事 1 到 11 的编号施工。前一个故事的独立测试未通过时，MUST NOT 开始下一个。优先级标签 MUST NOT 改变该顺序。
- **FR-002**: 业务 JSON MUST 使用权威信封：`code`、`message`、`data`、`traceId`、`ts`。成功时 `code` 为 `0`。错误码以权威错误表为准。`message` MUST NOT 含堆栈、SQL、密钥或联盟推广位标识。
- **FR-003**: 表结构 MUST 与 [`docs/data-model.md`](../../docs/data-model.md) 一致，并通过迁移创建。MUST NOT 使用 MySQL。平台只有 `taobao`、`jd`、`pdd`、`vip`。
- **FR-004**: DAO 的常规 XML 映射 MUST 由集成的生成器产出。引入该生成器前 MUST 按宪章检索同类项目，并在权威技术栈表锁定精确版本，写明用它的哪一部分。手写 XML 只允许覆盖生成器表达不了的查询，MUST NOT 在 XML 中拼联盟业务，MUST NOT 复制 mall-guide。
- **FR-005**: 消费者 HTTP MUST 符合 [`docs/api-app.md`](../../docs/api-app.md)。需登录的接口在无凭证时 MUST 返回 `40100`。Demo 登录为手机号验证码。短信通道与 omino-sso 的创蓝字段对齐。仅本地允许模拟短信。生产 MUST NOT 使用模拟短信。
- **FR-006**: 首次登录携带有效且非本人的邀请码时，MUST 在同一事务写入 `app_user.inviter_id` 与邀请关系，并将该关系标为有效。`inviter_id` 写入后 MUST NOT 再改。MUST NOT 自己邀请自己。
- **FR-007**: 对话的开轮、事件流、停止和积分不足 MUST 符合 [`docs/conversation.md`](../../docs/conversation.md)。提交后 MUST 立刻返回本轮编号。事件进入共享流。订阅读取间隔 MUST 不超过 100 毫秒。断开订阅 MUST NOT 取消生成。停止 MUST 写入 `cancelled`。终态（`done`、`error`、`cancelled`、`credit_exhausted`）之后，该轮 Redis Stream MUST 再保留 30 分钟。未结束的轮由 Worker 按该契约超时写入 `error` 并结束。
- **FR-008**: 本功能 MUST NOT 实现意图图或图节点。`test` 与 `prod` 的 Worker MUST 调用 Agent。Agent 不可用，或测试与生产没有可分流模型时，本轮 MUST 以事件 `error` 结束，且 `code` 为 `50020`，MUST NOT 把样例商品写成成功的 `done`。假事件内容 MAY 只出现在自动化测试的测试双写或 `local`。事件名 MUST 使用对话契约中的锁定名称。
- **FR-009**: 商品详情、瘦快照、转链、浏览、收藏和合集 MUST 符合消费者契约。`salesCount` 与 `reviewCount` 未知时 MUST 为空，MUST NOT 为 0。未授权转链 MUST 返回 `40301`，且 `error.reason` 为 `NEED_AUTH`。MUST NOT 下发联盟推广位标识。
- **FR-010**: 四个平台的外部访问 MUST 只发生在平台适配层。搜品或详情失败 MUST 返回 `50010`。MUST NOT 实现美团。
- **FR-011**: 订单同步 MUST 维护每平台游标，并把平台原码映射为六种订单状态与三种结算状态。仅当已完成、待结算、已归因且用户分成大于 0 时，给下单用户写一条返佣流水。重复同步 MUST NOT 双写。本批订单写入与该平台游标推进 MUST 在同一事务。事务失败则游标 MUST 停在原处。入账事务 MUST 先锁定该用户钱包行。MUST NOT 给上级写第二笔分成。消费者订单响应 MUST NOT 含媒体佣金。分成比例 MUST 读取可热更新的 `commission.user-share-rate`。
- **FR-011a**: 本功能 MUST 提供返佣余额的提现申请（已登录消费者）和运营审核。实现前 MUST 先把路径、状态和打款通道写入 [`docs/api-app.md`](../../docs/api-app.md) 与 [`docs/api-admin.md`](../../docs/api-admin.md)。本规格不预写这些路径。申请时 MUST 把相应金额从返佣可用余额划入冻结额。拒绝 MUST 把该笔冻结额退回可用余额，且 MUST NOT 写提现流水。审核通过 MUST 在打款到收款账号成功之后，才扣减该笔冻结额并写一条 `wallet_ledger.type=withdraw` 流水。打款失败 MUST 保持该笔冻结额，MUST NOT 记成功流水，也 MUST NOT 把该次审核当作完成；运营 MUST 能再次打款，也 MUST 能改为拒绝并解冻。对话里的提现确认不在本功能。积分 MUST NOT 通过提现离开积分账户。修改可用余额或冻结额的事务 MUST 先 `SELECT ... FOR UPDATE` 锁定该用户钱包行。锁住之后 MUST 在同一事务里重读该笔提现，只有状态仍为 `pending` 才打款或拒绝。可用余额与冻结额 MUST NOT 为负。打款失败的响应 `message` MUST 说明未打出且冻结额未动。
- **FR-012**: 积分账户与返佣钱包 MUST 分户。购积分渠道只有 `wechat_pay`、`alipay`、`wallet`，三个渠道都必须能下单。`wallet` MUST 在下单当时、于已锁定该用户钱包行的同一事务内扣减返佣可用余额并增加积分。`wechat_pay` 与 `alipay` MUST 在验签通过后才入账；验签失败 MUST NOT 加积分；同一合法回调 MUST NOT 入账第二次。本功能用测试密钥构造合法回调完成验收，MUST NOT 把连上真实商户扣款作为完成条件。MUST NOT 提供积分提现或积分转回钱包。扣费、入账和支付回调只发生在服务端。对话工具 MUST NOT 修改积分或钱包。
- **FR-013**: 海报 MUST 只保存并下发模板原图与二维码矩形。MUST NOT 在服务端合成成品图。公开邀请查询 MUST NOT 返回邀请人昵称或手机号。
- **FR-014**: 工单的状态、优先级、证据、回复和改派 MUST 追加处理日志。建单 MUST 在同一事务写创建日志。知识库未命中 MUST 明确返回未命中。
- **FR-015**: 版本、特殊配置、公告和点对点站内信 MUST 符合消费者契约与管理契约。站内信 MUST NOT 被当成群发。缺少规定的客户端头时，业务请求 MUST 返回 `40001`。
- **FR-016**: 推荐问题同时上架 MUST NOT 超过 12 条。提示词键 MUST 固定为数据模型中的八个，只能改正文。模型密钥 MUST 以 AES-GCM 加密保存。读取接口 MUST NOT 返回明文。开轮 MUST 注入全部提示词和本轮命中的一条模型。本地且没有可分流模型时 MAY 不注入模型。测试与生产没有候选模型时 MUST NOT 调用对话服务。
- **FR-017**: 管理端身份 MUST 使用 omino-sso 的 Authorization Code + PKCE S256，由管理服务完成兑换。浏览器 MUST NOT 持有访问令牌。MUST NOT 自建管理员密码表。未登录 MUST NOT 访问运营业务接口。上帝视角票据在生产默认关闭；未开启时 MUST 返回 `40303`。开启后票据 MUST 带 `gv=1`，有效期 MUST NOT 超过 1 小时，并 MUST 写管理审计。
- **FR-018**: 运营 HTTP MUST 以 [`docs/api-admin.md`](../../docs/api-admin.md) 已写明的路径为闭集。工具 HTTP MUST 以 [`docs/api-internal.md`](../../docs/api-internal.md) 的白名单为闭集。内部工具接口 MUST NOT 再调用对话服务。两个服务端 MUST NOT 互相引用。
- **FR-019**: 登录、回调、登出的管理路径在实现前 MUST 先写入 [`docs/api-admin.md`](../../docs/api-admin.md)。本规格不另选一套路径。提现申请与审核的路径按 FR-011a 先写入契约再实现。契约文档没有列出的工单运营和知识库运营路径，本功能不新造。`withdrawal` 表仍按数据模型创建。

### Key Entities

实体与列以 [`docs/data-model.md`](../../docs/data-model.md) 为准。本功能涉及的业务对象是：

- **终端用户与邀请**：用户、登录绑定、邀请关系、邀请人标识。邀请码不可变。绑定即有效。
- **对话与记忆**：会话、消息、浏览等事件、语义记忆。工作记忆使用对话组件的官方存储，本功能不另建一套业务表，也不跑对话图。
- **商品**：瘦快照、合集、合集项、收藏、点击归因、平台授权。不是全量商品库。
- **订单与钱**：统一订单、同步游标、钱包、钱包流水、提现记录、积分账户、积分流水、积分套餐、积分订单、模型用量。
- **运营内容**：海报模板、知识库、工单与处理日志、版本、特殊配置、公告、站内信、推荐问题、八条提示词、模型配置、管理审计。管理员密码不在本库。

### Out of Scope

- Vue、消费者 H5、iOS、Android 的页面与交互。本功能只提供它们将来调用的 HTTP。
- 对话图、意图节点、工具编排。`test` 与 `prod` 不得用假事件代替对 Agent 的调用。假事件只允许在测试双写或 `local`。
- Flutter、React Native、Kotlin Multiplatform。
- 自建管理员账号密码，以及让消费者登录走统一身份。
- 服务端合成邀请海报、成品图预览接口。
- 给上级写第二笔返佣。
- 复制 mall-guide 的源码、映射、表名或包名。
- 美团，以及自营购物车、商品货款、第三方售后。
- 积分提现，以及把积分转回返佣钱包。
- 连接真实微信或支付宝商户完成扣款。三个渠道的下单、钱包当场入账，以及用测试密钥验签回调仍在本功能内。
- 用图中断充当用户停止生成。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户故事 1 到 11 各至少有一项自动化测试或一条可重复的调用检查，并且该项通过。
- **SC-002**: 需登录的消费者请求在没有凭证时，100% 得到未登录结果 `40100`。
- **SC-003**: 未授权平台的转链请求，100% 得到 `40301`，且原因是需要授权；抽查响应不含联盟推广位标识。
- **SC-004**: 同一笔已完成且待结算的订单，连续同步两次后，下单用户名下的返佣流水仍为 1 条，可用余额只增加一次。
- **SC-005**: 未登录调用管理业务接口时，100% 进不去，且响应中没有用户资料、订单或密钥。
- **SC-006**: 抽查模型读取、转链、消费者订单和审计记录，不出现密钥明文、联盟推广位标识或媒体佣金。
- **SC-007**: 海报拉取结果只含模板与矩形。不存在由服务端返回成品海报的成功路径。
- **SC-008**: 同一笔提现先打款失败再成功时，提现流水仍为 1 条。拒绝与成功不能同时成立。并发申请后可用余额与冻结额都不为负。失败后的记录仍是 `pending`，且能按该状态查到。

## Assumptions

- 本功能的验收者是仓库研发。购物用户和运营是接口的使用者，但本功能不交付页面。
- 字段、路径、枚举、事件名和错误码只维护在 `AGENTS.md` §5 与 `docs/data-model.md`、`docs/api-app.md`、`docs/api-admin.md`、`docs/api-internal.md`、`docs/conversation.md`。本规格描述行为和验收，不复制列定义。
- 管理端登录、回调和登出的具体路径尚未在管理契约中锁定。实现这些路径的同一次变更必须先把路径写入该文档。
- 返佣提现的申请和运营审核属于本功能。申请冻结可用余额；拒绝解冻；打款成功才扣减冻结额并记提现流水；打款失败保持冻结，可再次打款或拒绝解冻。消费者契约和管理契约目前还没有这些路径和打款通道，实现前的同一次文档变更必须先补上。规格不预写路径。积分提现和积分转回钱包仍然禁止。对话里的提现确认属于后续对话功能。自动化测试必须能分别制造打款成功和打款失败，不把某一次真实商户出款当作唯一验收。
- 短信与联盟的官方组件按宪章检索后写入技术栈表再引入。本地开发可以用模拟短信。联盟测试不依赖真实联盟账号时，失败仍必须返回契约中的平台失败码。微信和支付宝购积分不要求真实商户扣款：验收使用测试密钥构造验签通过的回调，并且只入账一次。
- XML 映射生成器的具体项目在计划阶段选定并锁定版本。规格只要求集成生成器，不预选库名。
- 对话图、页面、官网和落地页展示属于后续功能。落地页公开校验邀请码所需的查询在本功能提供。`test` 与 `prod` 的对话 Worker 调用 Agent，本功能不实现对话图。样例事件只用于 `local` 和测试双写。
- 本地可以关闭配置中心并使用契约中的默认分成比例与积分比例。测试与生产必须能读取这些热配置。
