## Clarifications

### Session 2026-10-30

- Q: 配了测试密钥之后，如果官方拒绝请求，或者成功了但没有商品、没有新订单，搜品、详情、转链和订单增量还算验收通过吗？ → A: 必须成功。四个平台的搜品、详情、转链都要拿到成功结果，订单增量每个平台至少写入一笔订单。联盟账号已有这些数据。唯品会调用需要 IP 白名单；来源不在白名单时本地调用可以失败，该失败不算通过。白名单来源必须达到同样的成功结果。

## User Scenarios & Testing *(mandatory)*

本功能把 feat 2 的四个平台适配器从「有密钥也直接失败」改成真实出站。购物用户因此能搜到真实商品、看到真实详情、在已授权后拿到购买链接，已完成订单仍只入账一次。页面和对话图不在本功能。

施工顺序是用户故事 1 到 4。故事 1 未通过，不得开始后面的出站。字段、错误码和入账规则以权威文档与 feat 2 已交付的行为为准，本规格不另写一套。

### User Story 1 - 官方包能装进本机并传到私有仓库 (Priority: P1)

研发把五份官方包放进本仓库的 Java SDK 目录，用一条命令装进本机 Maven 仓库，用另一条命令上传到操作者自己的私有仓库。构建在依赖这些包之前，技术栈表已经写上精确坐标、版本，以及用它的哪一部分。

**Why this priority**: 这些包不在 Maven Central。没有它们，后面的真实出站无法编译。

**Independent Test**: 目录里能找到五份坐标对应的 jar（淘宝另含 sources jar）。安装命令把它们装进本机仓库。上传命令的脚本和仓库文件里没有私有仓库口令。技术栈表能对上这五份坐标。

**Acceptance Scenarios**:

1. **Given** 参考仓库 `sdks` 里已有的官方二进制，**When** 复制到 `services/java/sdks`，**Then** 存在且仅使用这五份坐标：`com.taobao:taobao-sdk-java:20250925`（含 sources jar）、`com.jd:open-api-sdk:20250925`、`com.pdd:pop-sdk:1.10.16`、`com.vip:vop-sdk:20250214094310`、`com.vip:osp-sdk:20250214094310`。旁边已有的 pom 一并复制。淘宝 sources jar 必须在。
2. **Given** 上述文件已在目录中，**When** 运行安装命令，**Then** 命令通过 `mvn install:install-file` 把五份坐标装进本机 Maven 仓库。
3. **Given** 操作者本机 `settings.xml` 已配置私有仓库，**When** 运行上传命令，**Then** 命令通过 `mvn deploy:deploy-file` 上传这五份坐标。仓库地址和口令只来自该 `settings.xml`。
4. **Given** 本仓库的提交内容，**When** 检查 `services/java/sdks` 与技术栈表，**Then** 找不到私有仓库口令、联盟密钥和 PID。`AGENTS.md` §2 已锁定上述精确坐标和版本，并写明用哪一部分。
5. **Given** 复制结果，**When** 对照参考仓库，**Then** 复制物限于 jar、随包 pom 和淘宝 sources jar。参考仓库的源码、封装类、调用代码和它自己的安装脚本不进入本仓库。

### User Story 2 - 有密钥时能搜到商品并看详情 (Priority: P1)

已配置测试密钥且联盟账号已有商品时，淘宝、京东、拼多多的搜品和详情必须返回至少一条符合现有契约的成功结果。唯品会在来源 IP 已加入白名单时同样必须成功。任一必需密钥为空时，结果仍是 `50010`，且该次调用不发出站请求。平台没给销量或评价数时，这两项仍为空。

**Why this priority**: 这是真实出站的第一条用户可见结果。转链和订单都依赖同一批适配器已经会说话。

**Independent Test**: 淘宝、京东、拼多多在测试密钥下各得到至少一条搜品结果和一条详情。唯品会在来源 IP 已加入白名单时达到同样结果；白名单外的失败不算通过。清空该平台密钥后再调用，得到 `50010`，出站次数为 0。官方未返回销量时，`salesCount` 与 `reviewCount` 为空。

**Acceptance Scenarios**:

1. **Given** 某一平台的测试密钥已配齐，且联盟账号已有商品，**When** 搜品并读取其中一条详情，**Then** 搜品至少返回一条商品，详情返回该商品的契约字段。空列表或官方拒绝不算本次通过。唯品会仅在来源 IP 已加入白名单时执行本条。
2. **Given** 该平台任一必需密钥为空，**When** 搜品或读取详情，**Then** 结果为 `50010`，且不发出站请求。
3. **Given** 密钥已配齐但官方返回失败或超时，**When** 搜品或读取详情，**Then** 结果为 `50010`。`message`、响应体和日志不含密钥、PID、relationId。
4. **Given** 官方未返回销量或评价数，**When** 读取详情或瘦快照，**Then** `salesCount` 与 `reviewCount` 为空，不得写成 0。

### User Story 3 - 已授权后才能把链接换成可购买链接 (Priority: P1)

用户尚未授权该平台时，转链仍是 `40301`，原因 `NEED_AUTH`，并且不调用官方转链。已经授权且应用密钥齐全时，转链打到官方，并继续留下点击归因。响应不下发 PID。

**Why this priority**: 购买链接是联盟密钥真正出站的地方。门闩松了，未授权用户也会打到官方。

**Independent Test**: 未授权用户请求转链，得到 `40301` / `NEED_AUTH`，官方转链出站次数为 0。已授权且密钥齐全时，转链返回可购买链接并留下点击归因。唯品会的成功样本在白名单 IP 上取得。抽查响应无 PID、无密钥。

**Acceptance Scenarios**:

1. **Given** 用户尚未授权该平台，应用密钥即使已经配齐，**When** 请求转链，**Then** 结果为 `40301`，`error.reason` 为 `NEED_AUTH`，且不调用官方转链。
2. **Given** 用户已授权、该平台密钥齐全，且账号已有可转链商品，**When** 请求转链，**Then** 官方返回可购买链接，并留下点击归因。未安装对应 APP 时的链接形态仍按消费者契约。唯品会的本条在白名单 IP 上执行。空结果或官方拒绝不算本次通过。
3. **Given** 转链成功或失败，**When** 查看响应、错误 `message` 和日志，**Then** 其中没有联盟密钥、PID、relationId。
4. **Given** 该平台密钥为空，**When** 已授权用户请求转链，**Then** 结果为 `50010`，且不发出站请求。

### User Story 4 - 真实订单仍按原游标入账一次 (Priority: P2)

订单增量继续使用 feat 2 的每平台游标。拉到的官方订单与游标推进、返佣入账仍在同一事务。同一笔已完成且待结算的订单重复同步，钱包流水仍只有一条。

**Why this priority**: 出站换成真实报文后，入账规则不能被改写。钱的验收与搜品分开，避免为了看商品而放开双写。

**Independent Test**: 淘宝、京东、拼多多在测试密钥下各至少写入一笔订单，游标在该批写入成功后前进。唯品会的这笔写入在白名单 IP 上验收。把同一笔已完成且待结算的订单再同步一次，下单用户的返佣流水仍为 1 条。密钥为空时同步得到 `50010` 且不发出站请求，游标停在原处。

**Acceptance Scenarios**:

1. **Given** 该平台测试密钥已配齐，且联盟账号已有订单，**When** 执行订单增量，**Then** 请求打到该平台官方订单接口，至少写入一笔统一订单，状态映射仍是六种订单状态和三种结算状态。没有新订单或官方拒绝不算本次通过。唯品会在白名单 IP 上执行本条。
2. **Given** 本批订单里有已完成、待结算、已归因且用户分成大于 0 的订单，**When** 同步入账，**Then** 只给下单用户写一条返佣流水。订单写入、入账和该平台游标推进在同一事务。事务失败时游标停在原处。
3. **Given** 同一笔订单已经入账，**When** 再同步一次，**Then** 不新增返佣流水，可用余额不因此再增加。
4. **Given** 该平台密钥为空，**When** 执行订单增量，**Then** 结果为 `50010`，不发出站请求，不推进游标。

---

### Edge Cases

- 平台应用标识或密钥只配了一半：视为未配置，返回 `50010`，出站次数为 0。不读取淘宝 PID 和京东站点号。
- 官方超时、限流或返回业务错误：返回 `50010`。错误文案面向调用方，不包含密钥、PID、relationId、堆栈或 SQL。这类结果不算正向验收通过。
- 官方接受了请求，但商品列表或订单列表为空：不算正向验收通过。改用已有数据的联盟账号再取成功样本。
- 唯品会从来源 IP 不在白名单的机器调用：调用可以失败。该失败不算正向通过，也不代替白名单环境上的成功样本。白名单来源必须拿到搜品、详情、转链和至少一笔订单。
- 未授权转链与「应用密钥为空」同时发生：先按授权门闩返回 `40301`。密钥是否为空不改变未授权的结果，也不因此发出转链请求。
- 官方商品没有销量或评价数：保存与返回均为空，列表和详情都不得显示成 0。
- 请求使用美团平台码，或要求新增第五个平台码：拒绝。仓库不增加美团适配器、美团密钥或美团订单同步。
- 私有仓库未在 `settings.xml` 配置：上传命令失败退出。不得改用写进 Git 的地址或口令。
- 参考目录里某份坐标没有随包 pom：仍然发布该坐标的 jar。不为此复制参考仓库的 Java 源码或脚本。
- 消费者接口与内部工具接口查询同一平台：都走平台适配层。内部工具不直连联盟，也不新增工具名。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 本功能 MUST 把五份官方包放到 `services/java/sdks`，坐标与版本固定为：`com.taobao:taobao-sdk-java:20250925`（含 sources jar）、`com.jd:open-api-sdk:20250925`、`com.pdd:pop-sdk:1.10.16`、`com.vip:vop-sdk:20250214094310`、`com.vip:osp-sdk:20250214094310`。复制物限于 jar、随包 pom 和淘宝 sources jar。
- **FR-002**: 构建依赖这些包之前，MUST 先在 `AGENTS.md` §2 锁定上述精确坐标和版本，并写明用哪一部分、不用哪一部分。这些包不在 Maven Central，不得改用别的坐标顶替。
- **FR-003**: `services/java/sdks` MUST 提供两条命令。安装命令 MUST 用 `mvn install:install-file` 把五份坐标装进本机 Maven 仓库。上传命令 MUST 用 `mvn deploy:deploy-file` 上传到私有仓库。私有仓库地址和口令 MUST 只从操作者本机 `settings.xml` 读取，MUST NOT 写入 Git、日志或命令文件。
- **FR-004**: 淘宝、京东、拼多多、唯品会的搜品、详情、转链和订单游标增量 MUST 只在平台适配层调用官方包。业务层、管理端和对话图 MUST NOT 直接调用这些包。唯品会出站使用 `vop-sdk` 与 `osp-sdk` 这两份包。
- **FR-005**: 搜品、详情和订单增量在该平台任一必需密钥为空时 MUST 返回 `50010`，且 MUST NOT 发出站请求。转链先按 FR-006 检查用户授权；已授权之后若密钥为空，MUST 返回 `50010`，且 MUST NOT 发出站请求。密钥已配齐但上游失败时，MUST 返回 `50010`。
- **FR-006**: 用户尚未授权该平台时，转链 MUST 返回 `40301`，且 `error.reason` 为 `NEED_AUTH`，MUST NOT 调用官方转链。已授权且密钥齐全时，转链 MUST 打到官方，并按现有契约留下点击归因。
- **FR-007**: `salesCount` 与 `reviewCount` 在官方未给出时 MUST 为空，MUST NOT 为 0。
- **FR-008**: 响应、错误 `message` 和日志 MUST NOT 出现联盟密钥、PID 或 relationId。消费者转链响应 MUST NOT 下发 PID。
- **FR-009**: 订单增量 MUST 沿用 feat 2 的每平台游标。本批订单写入、符合入账条件时的返佣流水，以及游标推进，MUST 在同一事务。重复同步 MUST NOT 双写流水。事务失败时游标 MUST 停在原处。入账条件、六种订单状态、三种结算状态和「不给上级写第二笔」保持 feat 2 的规则。
- **FR-010**: 平台码 MUST 仍只有 `taobao`、`jd`、`pdd`、`vip`。MUST NOT 新增平台码，MUST NOT 实现美团，MUST NOT 接入大淘客。
- **FR-011**: 淘宝、京东、拼多多在测试密钥下的正向验收 MUST 同时满足：搜品至少一条商品、详情至少一条、已授权转链至少一条可购买链接、订单增量至少写入一笔订单。空结果与官方拒绝 MUST NOT 计为正向通过。唯品会 MUST 在来源 IP 已加入其白名单的环境上达到同样四条；白名单外的失败 MUST NOT 计为正向通过。

### Key Entities

本功能不新增表。涉及的既有对象以 [`docs/data-model.md`](../../docs/data-model.md) 为准：

- **官方包**：五份固定坐标的二进制。它们不是业务表，也不代表商品全量库。
- **平台授权**：用户是否已授权某平台。转链门闩只看这个状态。
- **瘦快照与点击归因**：详情里的销量、评价数、商品链接，以及转链成功后的点击记录。
- **统一订单、同步游标、钱包流水**：真实订单回传后仍按原游标和原入账规则写入。

### Out of Scope

- 管理后台页面、消费者 H5、官网、落地页、iOS、Android 的页面与交互。
- 对话图、意图节点、工具编排。内部工具继续调用现有白名单，由平台适配层出站。
- 新的平台码、美团、大淘客。
- 服务端合成邀请海报。
- 复制参考仓库的源码、封装类、调用代码、映射、表名、包名，以及它的安装或上传脚本。
- 把私有仓库地址或口令、联盟密钥、PID 写入 Git。
- 改写入账条件、积分规则、提现规则，或给上级写第二笔返佣。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: `services/java/sdks` 中五份坐标的 jar 齐全，淘宝 sources jar 在其中。对照参考仓库，复制进来的文件里没有 Java 源码和参考仓库的脚本。
- **SC-002**: 安装命令在本机 Maven 仓库中装上全部五份坐标。上传命令的仓库文件不含口令；操作者已配置私有仓库时，上传命令能把五份坐标传上去。
- **SC-003**: 淘宝、京东、拼多多各有一套成功样本：至少一条搜品、一条详情、一条可购买链接、一笔新写入的订单。唯品会在 IP 白名单内的环境上具有同样四套样本。抽查这些响应，没有 PID 和密钥。
- **SC-004**: 四个平台在密钥为空时，搜品、详情、转链、订单增量 100% 返回 `50010`，且出站次数为 0。
- **SC-005**: 未授权转链 100% 返回 `40301`，原因为 `NEED_AUTH`，官方转链出站次数为 0。
- **SC-006**: 同一笔已完成且待结算的订单连续同步两次后，下单用户的返佣流水仍为 1 条，可用余额只增加一次。
- **SC-007**: 抽查至少一条官方未给销量的详情，`salesCount` 与 `reviewCount` 为空。

## Assumptions

- 验收者是仓库研发。购物用户能因此得到真实商品和购买链接，但本功能不交付页面，也不交付对话图。
- feat 2 的适配器、转链门闩、订单游标和一次入账已经在 main。本功能替换出站，不改这些规则的口径。
