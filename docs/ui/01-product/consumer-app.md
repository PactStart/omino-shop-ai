# 第 1 层：消费者 APP 产品与信息架构

## 1. 设计任务

omino 觅选是面向 20–50 岁中文消费者的对话型购物助手。核心体验是“说出需求 → 跨平台选品 → 看详情 → 跳第三方平台购买”，不是传统电商首页，也不承载购物车或自营结算。

设计关键词：可信、干净、好开口、价格清楚、不花哨。体验优先级依次为：完成购物决策、理解当前系统状态、保护资金与隐私、提高操作效率、品牌表达。

包名固定 `com.omino.shopai`。商店展示名锁定为 **omino 觅选**。口号是 **omino｜觅选，先问再买，越用越懂你。**

标志放在 [`docs/ui/logo/`](../logo/)。图形是购物车加对话气泡，车斗里是 AI。五套与主题一一对应，默认用晴空绿。根目录的 `v1.png` 到 `v5.png` 是 1024 的主图。每种主题目录里还有商店和主屏用的边长：1024、512、256、192、180、167、152、144、120、114、96、87、80、76、72、60、58、48、40、29、20。

## 2. 用户与核心任务

| 用户目标 | 关键任务 | 成功标准 |
| --- | --- | --- |
| 找到合适商品 | 对话表达需求、补充条件、查看商品/合集 | 用户知道推荐理由并能继续比较 |
| 去第三方购买 | 查看详情、处理联盟授权、打开第三方平台 | 只有详情页出现“去购买”，跳转路径明确 |
| 跟踪订单和收益 | 筛选订单、看返佣、看钱包与提现 | 积分和人民币资产不混淆 |
| 管理账号与权益 | 登录、资料、授权、站内信、邀请、设置 | 敏感信息始终脱敏，危险动作可辨识 |
| 获得帮助 | 对话问规则、创建并查看工单 | 建单不伪装为问题已解决 |

## 3. 正式信息架构

当前底栏是对话、订单、我的。登录成功后仍默认进入对话。商城本期不做。

```text
App
├── 对话 chat
│   ├── 会话历史 chatHistory
│   ├── 商品合集 goodsCollection
│   └── 商品详情 goodsDetail
├── 订单 orders
└── 我的 me
    ├── 个人资料 profile
    ├── 浏览记录 goodsHistory
    ├── 收藏 goodsFavorites
    ├── 积分 credits → 套餐 / 流水 / 支付单
    ├── 钱包 wallet → 提现 / 提现记录
    ├── 联盟授权 authorizations
    ├── 邀请 invite
    ├── 工单 tickets → ticketDetail
    ├── 站内信 inbox
    └── 设置 settings → 显示 / 推送 / 关于
```

登录、详情、提现表单、全屏更新、Modal 和 Drawer 不显示底部 Tab。根 Tab 切换保留各自的滚动和筛选状态。

## 4. 商城

商城本期不做，底栏不出现商城。首页、搜索和内嵌页的结构留在 [`mall.md`](../05-screens/mall.md)，不进入当前画板。

## 5. 全局业务边界

- 商品卡只负责进入详情，不出现购买或转链按钮。
- 唯一“去购买”位于商品详情页。有商品的订单卡片点进去也是这一页。
- 无购物车、站内收银台、自营物流、平台 PID、relationId 或完整收款账号。
- 积分没有 `¥`；钱包金额必须有 `¥`。钱包只能单向购买积分，积分不能提现或转回钱包。
- 无销量、评价或物流信息时隐藏或显示明确空态，不能用 `0` 或虚构信息填充。
- 刷新、切后台或 SSE 断开不等于用户停止生成。
- 危险操作使用红字线框，不能与品牌实心主按钮混淆。
- H5 上帝视角 JWT `gv=1` 时必须常驻提示条，并禁用生产账号注销。

## 6. 多端一致与差异

信息架构、字段语义、状态和组件角色三端一致；导航容器、键盘、安全区、返回手势、系统分享与外部 APP 打开方式遵循各平台原生习惯。

| 能力 | Android / iOS | H5 |
| --- | --- | --- |
| 积分支付渠道 | 微信、支付宝、钱包 | 仅钱包 |
| 去购买 | deeplink → universal link → Web 兜底 | fallback URL；没有则 click URL |
| 邀请海报 | 端上合成并走系统/微信/QQ分享 | Canvas 合成，使用浏览器能力 |
| 上帝视角 | 不提供 | 顶部常驻 `godViewBar`，不可关。地址上的 `access_token` 读入本地后立刻从地址去掉。该态禁止注销 |
| Tab 与返回 | 原生导航与系统手势 | Web History 与浏览器返回 |

## 7. Figma 生成边界

生成 IA 或全局页面地图时，只允许使用本文列出的页面。任何新增页面、Tab 或商业能力先放入 `Exploration`，不得混进 `Ready for dev`。正式画板必须标注 Page ID、路由、平台和状态。
